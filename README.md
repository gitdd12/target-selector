# 코어 찾기 (베타 프로토타입)

AI 인터뷰어와 채팅으로 경험을 이야기하면, 스펙(질문흐름 v0.15 / 결과지 작성 기준 v0.13)에 따라 결과지를 만들어주는 서비스입니다.

## 구조 한눈에 보기

| 폴더 | 하는 일 |
|---|---|
| `specs/` | 스펙 원문(마크다운). **규칙을 바꾸려면 여기 파일만 새 버전으로 바꾸면 됩니다.** |
| `data/` | O*NET 직업 데이터(CSV 2개) |
| `src/lib/specs.ts` | 스펙을 제목 단위로 잘라서 역할별(인터뷰어·기록 정리·코어 판정·결과지·직업)로 조립 |
| `src/lib/interview.ts` | 인터뷰어 한 턴. 코어 이름·해석이 새면 걸러서 다시 쓰게 함 |
| `src/lib/pipeline.ts` | 창 종료 → 기록 정리 → 다음 창 / 코어 판정 → 결과지 → 직업 추천 |
| `src/lib/jobs.ts` | 직업 추천 1~3단계(백분위 → 상위 필터 → gap). 4~5단계는 AI가 함 |
| `src/lib/store.ts` | 저장소(Supabase, 키가 없으면 내 컴퓨터의 `.data` 폴더) |
| `src/components/` | 화면(동의 안내, 10초 대상 선택, 채팅, 결과지) |

## 베타 운영 방식 (스펙 결과지 v0.13 "전달 방식")

1. 참가자는 인터뷰(4개 창)를 마치면 **결과지를 바로 보지 못하고**, 이메일을 남깁니다(대화 기록과 분리 저장).
2. 이메일을 적는 동안 뒤에서 결과지 초안(코어 판정 → 초안 → 직업 추천 → 유명인 사례 초안)이 만들어집니다. 참가자에게는 보이지 않습니다.
3. 운영자가 검토용 원고를 만듭니다:
   ```
   npm run review -- list          # 참가자 목록·진행 상태
   npm run review -- <세션id>       # 남은 초안 단계를 마무리하고 review/<id>.md 생성
   ```
   원고에는 (1) 참가자에게 보낼 초안 (2) 내부 태그·코어 판정·직업 후보 (3) 유명인 사례 후보(전부 미검증, 출처 확인용 검색어 포함) (4) 원문 대화가 들어 있습니다.
4. 출처를 확인해서 통과한 것만 결과지에 넣고, 3일 안에 이메일로 보냅니다.
5. 참가자 수 상한은 환경변수 `MAX_SESSIONS`(기본 30)입니다. 다 차면 첫 화면에 마감 안내가 나옵니다.

## 내 컴퓨터에서 돌려보기

1. Node.js 설치(이미 되어 있음).
2. `.env.example`을 복사해 `.env.local`을 만들고 `LLM_API_KEY=` 뒤에 Anthropic 키를 붙여넣기.
3. 터미널에서:
   ```
   npm install
   npm run dev
   ```
4. 브라우저에서 http://localhost:3000 열기. 저장은 `.data/sessions/`에 JSON으로 쌓입니다.

`npm run check` : 스펙 조립·직업 후보 계산이 정상인지 (AI 호출 없이) 빠르게 점검합니다.

## 스펙 문서를 새 버전으로 바꾸려면

1. 새 docx를 마크다운으로 변환:
   ```
   powershell -File scripts/docx-to-md.ps1 -Docx "..\질문흐름_v0.15.docx" -Out "specs\질문흐름_v0.15.md"
   ```
2. `specs/`에서 옛 버전 파일을 지웁니다(가장 높은 버전 번호 파일이 자동으로 쓰입니다).
3. `npm run check`로 섹션 제목이 다 잡히는지 확인합니다. 제목이 바뀌어 못 찾으면 에러가 납니다(조용히 빠지지 않음).
4. 참가자 기록에는 어느 스펙 버전으로 진행됐는지가 자동 저장됩니다.

## 배포 (베타 링크 만들기)

1. Supabase 프로젝트를 만들고 `supabase/schema.sql`을 SQL Editor에서 한 번 실행.
2. Vercel에 이 폴더를 올리고 환경변수 `LLM_API_KEY`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, (선택) `BETA_CODE`, `CONTACT_EMAIL` 입력.
3. 나온 주소를 베타 참가자에게 전달.

## 알아둘 점

- 참가자 기록은 Supabase의 `sessions` 표에 JSON으로 저장됩니다. 분석 기록(`records`), 코어 판정(`final`), 결과지(`report`), 진행 로그(`log`)가 모두 들어 있어서 표 화면에서 바로 볼 수 있습니다.
- 모델은 `src/lib/config.ts`(또는 환경변수 `MODEL_INTERVIEWER` 등)에서 역할별로 바꿀 수 있습니다.
- `/privacy` 안내문은 초안입니다. 공개 전에 전문가 검토를 받으세요.

## 남용 방지 (토큰 낭비 막기)

| 장치 | 내용 |
|---|---|
| 메시지 길이 | 한 번에 2,500자까지 |
| 창별 상한 | 경험 창 40회, 가치관 창 20회를 넘으면 그 창을 강제로 닫음(그 전에 16회·8회부터 AI에게 "슬슬 정리하라"고 알림) |
| 전체 상한 | 한 사람이 인터뷰 전체에서 70회·45,000자를 넘으면 그 창을 닫고 바로 결과지 단계로 넘어감 |
| 도배 방지 | 같은 사람이 1.5초 안에 다시 보내면 거절, 같은 IP에서 10분에 90회 초과하면 AI를 부르기 전에 거절 |
| 엉뚱한 요청 | 코딩·번역·지시문 공개 요구 등은 정중히 거절하고 인터뷰로 복귀. 세 번 넘게 반복되거나 무의미한 입력이 이어지면 인터뷰 중단(오용 표시, 결과지 초안은 만들지 않음) |
| 참가자 수 | `MAX_SESSIONS`(기본 30). 새 세션 생성도 같은 IP에서 1시간에 12번까지 |
| 비용 확인 | 세션마다 AI 호출 횟수·토큰 사용량이 저장되고 `npm run review -- list`에 표시됨 |

**직접 하실 것:** Anthropic 콘솔(console.anthropic.com)에서 월 사용 한도(spend limit)를 꼭 걸어두세요. 서비스 밖에서 걸 수 있는 가장 확실한 안전장치입니다(메뉴 이름은 화면에 따라 조금 다를 수 있음). 그리고 `BETA_CODE`를 설정해서 링크를 아는 사람 중에도 코드를 아는 사람만 시작하게 하는 것을 권합니다.

## 시험 돌려보기 (AI 호출, 비용 발생)

```
npm run simulate                 # 가상 참가자(다른 AI)로 인터뷰 한 판을 끝까지 돌림(1판에 약 1.5~2달러 수준)
npm run review -- <세션id>       # 결과 검토용 원고 만들기
```
`review/` 폴더에 대화 전문(`sim-…-transcript.txt`)과 검토용 원고(`<id>.md`)가 생깁니다.

## 스펙의 최신본

`specs/`의 마크다운 파일이 최신본입니다(질문흐름 v0.15, 결과지 v0.13). 루트의 옛 docx는 참고용입니다. 스펙을 바꿀 때는 이 파일을 직접 고치고 버전을 올린 뒤, 변경 이유를 `docs/`에 남깁니다.

## 검토 화면

환경변수 `REVIEW_PASSWORD`를 정하면 `/review` 주소에서 비밀번호로 들어가 참가자 목록, 결과지 초안(참가자 화면과 같은 모양의 미리보기), 검토 메모, 유명인 사례 초안(검색 링크 포함), 원문 대화를 볼 수 있습니다. 이메일 본문용 글 복사 버튼도 있습니다. 비밀번호를 정하지 않으면 이 화면은 꺼져 있습니다.

시험 참가자를 지울 때는 `npm run cleanup -- <세션id>`, 저장소 연결 점검은 `npm run dbtest`.

- 주소: https://core-finder-alpha.vercel.app (Vercel 프로젝트 `wai18/core-finder`, Supabase 프로젝트 `xmnwqemvuqgdvwtnksdf`)
- 코드를 고친 뒤 다시 올리기: `npx vercel deploy --prod --yes`
- 환경변수(Vercel에 저장됨): LLM_API_KEY, SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, CONTACT_EMAIL, REVIEW_PASSWORD. 값을 바꾸려면 Vercel 화면(Settings → Environment Variables)에서 고치고 다시 배포해야 반영됩니다.
- 배포된 주소로 인터뷰 한 판 전체 시험: `npm run e2e -- https://core-finder-alpha.vercel.app` (AI 비용 약 $2, 시험 참가자가 저장소에 남으니 끝나고 `npm run cleanup -- <세션id>`로 지우기)
- 실측 시간(서버 제한 300초): 인터뷰 한 턴 수 초, 창 종료 기록 정리 8~45초, 결과지 초안 단계 34~77초.
- 시험 중 잡은 문제: Vercel에 옮긴 비밀 값 앞에 눈에 안 보이는 표식이 붙어 저장소 접속이 실패 → 코드가 값 앞뒤를 정리하도록 방어(`src/lib/env.ts`). AI가 형식 밖 값을 쓰면 한 번 다시 요청.

## 개발용 미리보기 (/dev)

`REVIEW_PASSWORD`를 정하고 `/review`에서 로그인한 뒤 `/dev`를 열면, **질문에 답하지 않고** 화면을 바로 볼 수 있습니다. 가짜 데이터로 실제 화면 컴포넌트를 그대로 그리며 AI를 부르지 않아 비용이 들지 않고 아무것도 저장하지 않습니다.

- 첫 화면, 10초 대상 고르기 4단계, 채팅 상태들(대화 중·생각 중·재진술 카드·카드 뒤·정리 중·오류·가치관 창), 이메일 화면
- `/dev/prompts`: 스펙을 역할별로 조립한 **AI 지시문 전문**과 고정 문구. 스펙을 고쳤을 때 반영됐는지 AI 호출 없이 확인
- 새 화면을 추가하면 `src/lib/devScreens.ts`와 `src/components/DevScreen.tsx`에 등록
