다른 컴퓨터에서 이어서 작업할 때 이 문서부터 읽으세요. 이 폴더 전체가 프로젝트입니다.

## 1. 지금 상태 한 줄 요약
- 서비스: AI 인터뷰(4개 창) → 코어 판정 → 결과지. 베타(지인 대상), 결과지는 운영자가 검토한 뒤 이메일로 보냄.
- 실제 주소: https://core-finder-alpha.vercel.app (Vercel 프로젝트 `wai18/core-finder`)
- 최신 배포까지 반영됨. 마지막 배포 내용: 결과지 v0.22(직업 후보 개선, 신뢰도 근거 문장, 해 볼 일 개선), 인터뷰 끝 팝업(현재 상태 고르기), 직접 해 보기·기록해 보기, 코어 여러 개일 때 글머리 기호, O*NET 표기 등.
- 스펙 버전: 질문흐름 v0.20 / 결과지 작성 기준 v0.22 (`specs/` 폴더). 변경 이력은 `docs/스펙_변경기록_2026-09-19.md` (맨 아래가 최신).

## 2. 새 컴퓨터에서 시작하는 법 (비개발자용)
1. Node.js(LTS 버전)를 설치합니다. https://nodejs.org
2. 이 폴더를 원하는 곳에 풀어놓고, 터미널(PowerShell)에서 폴더로 들어갑니다.
3. 패키지 설치:  `npm.cmd install`
4. **`.env.local` 파일을 새로 만듭니다.** (보안 때문에 이 백업에는 들어 있지 않습니다. 원래 컴퓨터의 `.env.local`을 따로 옮기거나 각 서비스 화면에서 다시 가져오세요.) 필요한 변수 이름:
   - `ANTHROPIC_API_KEY` (Anthropic 콘솔에서 발급)
   - `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (Supabase 프로젝트 설정)
   - `REVIEW_PASSWORD` (운영자 검토 화면 비밀번호)
   - `BETA_CODE` (베타 참가 코드), `CONTACT_EMAIL` (결과지 아래 문의 메일)
   - (`VERCEL_OIDC_TOKEN`은 자동으로 생기므로 필요 없음)
   - 같은 값이 Vercel 프로젝트의 환경변수에도 들어 있습니다(`npx.cmd vercel env ls`로 이름 확인).
5. 로컬 실행: `npm.cmd run dev` → 브라우저에서 http://localhost:3000
6. 배포: `npx.cmd vercel login` 으로 로그인한 뒤 `npx.cmd vercel link`(프로젝트 wai18/core-finder 선택) → `npx.cmd vercel deploy --prod --yes`
   - 가끔 "Not authorized / deploy_failed"가 나오면 그냥 한 번 더 실행하면 됩니다.
7. PowerShell 실행 정책 오류가 나면 `npm` 대신 `npm.cmd`, `npx` 대신 `npx.cmd`를 쓰세요.

## 3. 자주 쓰는 명령
| 명령 | 하는 일 |
|---|---|
| `npm.cmd run dev` | 내 컴퓨터에서 실행 |
| `npm.cmd run lint` / `npx.cmd tsc --noEmit` | 오류 점검 |
| `npm.cmd run check` | 스펙 버전과 프롬프트 조립 점검 |
| `npm.cmd run review -- list` | 참가자 목록과 진행 상태 |
| `npm.cmd run review -- <세션id>` | 검토용 원고 만들기(review 폴더) |
| `npm.cmd run apply -- <세션id>` | `review/patches/<id>.json` 내용으로 결과지를 직접 써서 넣기(AI 호출 없음, 원본은 review/backup에 저장) |
| `npm.cmd run simulate` | 가상 참가자로 인터뷰 전체 시험(실제 API 호출, 1회 약 2달러). `PERSONA=multi` 등으로 인물 바꿈, `SITUATION=working|applying|exploring` |
| `npm.cmd run cleanup -- <세션id>` | 시험용 참가자 삭제 |

## 4. 폴더 지도
- `specs/` 스펙 원문(마크다운). 규칙을 바꾸려면 여기 파일을 새 버전으로 바꾸면 앱이 가장 높은 버전을 씁니다. 이전 버전은 `docs/이전스펙/`.
- `src/lib/prompts.ts` AI에게 주는 규칙(인터뷰어·기록·판정·결과지·인물). 결과지 문체 규칙은 `WRITER_RULES`. 직업 목록의 AI 규칙(검색 문장·업무 판정·근거 번역)은 `src/lib/jobPrompts.ts`.
- `src/lib/types.ts` 데이터 모양(결과지·세션·현재 상태·직업 목록). `src/lib/frame.ts` 고정 문구(직접 해 보기 공통 이유, 기록해 보기 네 질문, 직업 목록 안내, 끝맺음).
- `src/lib/reliability.ts` 신뢰도(무게 신호 2개=중, 3개=상, 4개=최상, 근거 문장). `src/lib/jobfinder.ts` 직업 목록 만들기(검색 문장 → 임베딩 검색 → 업무 판정 → 직업 점수 → 확장 → 목록 → 근거 재확인 → 번역, 설계는 `docs/직업추천_재설계_2026-09-25.md`). `src/lib/embed.ts` 검색 문장 임베딩과 업무 검색. `src/lib/onet31.ts` O*NET 31.0 데이터 읽기. 임시 숫자들은 `src/lib/config.ts`의 `JOBS`.
- `src/components/ResultView.tsx` 결과지 화면(+ `.module.css`). `JobLists.tsx` 코어 칸 안의 직업 목록(누르면 근거 업무가 펼쳐짐). 예전 결과지(대상 칸·어울리는 직업)도 그대로 보여줌. `SituationPicker.tsx` 인터뷰 끝 팝업. `Landing*.tsx` 랜딩(스크롤 장면).
- `src/app/api/sessions/[id]/...` 인터뷰·현재 상태·이메일·결과지 만들기 API. `src/app/r/[id]` 참가자용 결과지, `src/app/review/[id]` 운영자 검토·공개.
- `data/onet31/` O*NET 31.0 데이터(업무 문장·중요도, 직업 한국어 이름·설명, 업무 임베딩, 제외 직업, 시험 정답지). 자세한 건 그 폴더의 README. 예전 방식의 코어 점수 CSV와 `onet_tasks.json`은 2026-09-26에 지웠습니다(git 기록에 남아 있음).
- `docs/memory/` 이 프로젝트를 도와 온 AI의 기억 메모(프로젝트 결정사항, 사용자 선호). 새 AI에게 먼저 읽히면 이어서 작업하기 쉽습니다.

## 5. 이 프로젝트를 도와줄 AI에게 알려줄 것(사용자 선호)
- 사용자는 비개발자이고 한국어로 쉽게 설명해 주길 원합니다. 기술적 결정은 AI에게 맡깁니다.
- **"~할까?", "흠", "생각 말해줘" 같은 질문에는 의견만 답하고 바로 작업하지 않습니다.** 명령("~해줘", "~하자")일 때 작업합니다.
- **배포는 사용자가 요청할 때만** 합니다. 배포 전에 로컬에서 확인하고 결과를 알려줍니다.
- 결과지 문체는 해요체. 코어에는 이름을 붙이지 않고 "행동 문장"으로만 씁니다(예전의 여섯 코어 이름은 v0.31부터 내부 태그로도 쓰지 않음).
- 결과지는 "확정하지 않는다, 확인된 만큼만 말한다"는 태도를 지킵니다(과장·단정 금지, 자기계발서 같은 뻔한 말 금지).
- 개인정보 안내 문구 등 법적인 부분은 법률 자문이 아니므로 정식 공개 전에 전문가 확인이 필요합니다.

## 6. 남은 일(우선순위 감각)
1. **실제 인터뷰 한 번 끝까지 해 보기**: 인터뷰 끝 팝업 → 이메일 → 결과지 초안이 새 형식으로 나오는지 확인(가상 참가자 시험은 통과했지만 사람이 직접 한 적은 없음).
2. 결과지에서 코어가 1개뿐인 경우가 많을 수 있음: 무게 신호가 1개인 경험(예: 표 짜기)은 후보로만 남고 결과지에서 빠짐. 인터뷰가 그런 경험에서 두 번째 신호를 더 캐내는지 계속 확인.
3. 새 직업 목록의 임시 숫자(검색 30개, 확장 상위 20개, 일치도 기준 20%, 해 볼 일 문턱 40, 인용 0.5)를 베타 결과로 다시 맞추기. Supabase에 `cache` 표 만들기(`supabase/schema.sql`, 근거 번역 저장용 — 없어도 동작은 하지만 번역을 세션마다 새로 함).
4. 웹 즉시 공개: 지금은 이메일+3일 검토. 결과지 품질에 확신이 생기면 인터뷰 직후 웹 결과지로 바로 연결하고 인물 사례는 검증 후 자동으로 채우는 방식으로 바꾸기(이메일은 링크 저장·후속 질문용).
5. 결과지 글을 운영자가 화면에서 직접 수정하는 기능은 없음(현재는 `review/patches` + `npm run apply`).
6. 결과지 사진 공유(인스타 등): 지금은 텍스트 공유만. 폰 브라우저에서 카드를 이미지로 그려 공유 창에 넘기는 방식으로 가능(서버 API 불필요).
7. 랜딩 페이지는 실제 폰(주소창이 접히는 기기)에서 스크롤·검정 띠 여부를 더 확인.
8. 옛 시험 참가자 정리(Supabase에 남아 있는 세션들).
