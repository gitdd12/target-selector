앱은 `Core Project/core-finder/` (Next.js 16 + Supabase + Vercel, LLM은 Claude Opus 5). 스펙 원문은 `core-finder/specs/`, 변환 스크립트는 `scripts/docx-to-md.ps1`.

사용자가 정한 것 (2026-09-19):
- 기록 필드의 "분석자" 항목은 전부 시스템(LLM)이 채운다.
- 경험 2 창에는 경험 1의 어떤 정보(제목 포함)도 넘기지 않는다 — 사용자가 방금 말했으니 기억한다는 판단.
- 대상 선택: index.html 로직 그대로. 5점 이상이 4개 이하여도 지우기 화면을 거쳐 더 줄일 수 있어야 한다(1개까지). 화면 앞부분은 index.html을 많이 참고.
- 스펙 문서 자르기는 자동으로(제목 단위 조립). 실명(영훈·박종경)은 프롬프트에서 "한 참가자"로 치환.
- 개발 모델은 Opus/Sonnet 중 사용자가 물었고 Sonnet 5로도 충분하다고 답함(서비스 런타임 AI는 별개로 Opus 5).

**스펙의 최신본(source of truth)은 이제 core-finder/specs/의 마크다운 파일이다(질문흐름 v0.15, 결과지 v0.13).** 사용자가 "내가 말한 걸 네가 반영했으면 그게 최신 문서, 별도 최신 docx는 없다"고 확정함(2026-09-19). 스펙 변경은 이 md를 직접 고치고 버전을 올리며 docs/에 변경 이유를 남긴다. 루트의 옛 docx는 참고용 옛 버전.
- 결과지에서 여섯 단어는 내부 태그, 노출 금지. 사람마다 지은 문구로 이름 붙임. 영훈 사례 문구는 사용자 설명대로 내가 다시 씀(짜기 쪽 문구는 내가 지음, 검토 필요).
- 유명인 사례(해외 가능, 출처 있는 장면, 극단+대가+"내 규모에서는", 인물 코어 전체 서술은 미정)는 AI 초안만 만들고 운영자가 출처를 검증해야 노출. 검증된 것만 쌓는 방식.
- 베타는 결과지를 바로 안 보여주고 이메일(대화와 분리 저장) → 3일 안 검토 후 발송. `npm run review`로 검토 원고 생성. 참가자 상한 MAX_SESSIONS 기본 30(내가 정한 값).
- 실제 API로 시험한 교훈(2026-09-19): 인터뷰어를 자유 형식 글 + 적응형 사고로 받으면 매 턴 가깝게 답변 뒤에 생각 메모·가짜 참가자 대사·엉뚱한 문장이 붙었다. 사고를 끄고 출력을 JSON(reply+finish)으로 고정하니 0회. 기록·판정·결과지 등 나머지는 구조화 출력이라 문제없음. callJson의 max_tokens는 16000 이하여야 함(그 이상이면 SDK가 스트리밍을 요구). 인터뷰 1판 비용은 약 $1.5~2(토큰 실측, 단가는 캐시된 가격표 기준이라 콘솔에서 확인 필요). 시험은 `npm run simulate`.

## 결과지 v0.17 (2026-09-21)
- 코어는 이름(알기 등)이 아니라 행동 문장(behavior)으로만 화면에 보임. 글 구조: 경험(짧은 줄) / 파악한 코어 / 이 방식이 힘들어질 때. 신뢰도: 무게 신호 2개=상, 3개 이상=최상(코드 계산, Session.reliability).
- 저장된 예전 결과지는 화면만 고쳐선 안 바뀜 → 내가 직접 새로 써서 넣는 도구: `npm run apply -- <세션id>` (review/patches/<id>.json, 원본은 review/backup). AI 호출 없음.
- 직업 추천의 "(참고용)" 안내와 자격 요구 문구는 삭제. 인물 사례의 미검증 일화·억지 "내 규모" 문구도 뺌.
