# 직업 추천 재설계 + 스펙 미반영 논의 정리 (2026-09-25)

이 문서는 설계 기록이다. `specs/`는 앱이 바로 읽는 AI 지시문이라, 새 로직을 코드로 구현할 때 같이 새 버전으로 올린다(그 전에 스펙만 바꾸면 코드와 지시문이 어긋난다).

상태 표시: **[확정]** 합의됨 · **[제안]** 방향은 맞지만 세부 확인 필요 · **[결정 필요]** 님이 정해야 함 · **[반영됨]** 이미 코드에 들어감

---

## 1. 왜 바꾸나

지금 방식(결과지 작성 기준 v0.22 "직업 매핑 방법론"): 행동 → 6개 코어 중 하나로 압축 → O*NET 활동 41개를 6개로 묶은 점수표 → 백분위·gap → LLM이 10개 중 선정.

시험에서 드러난 문제(같은 사실관계로 인터뷰한 테스트 세션 2개):
- 두 세션의 추천 직업이 **하나도 겹치지 않았다**(응급구조사·수술 보조원 / 내시경 기사·단열 시공).
- "자소서 문단 순서 고치기"가 "다루기"로 압축된 뒤 장비를 조정하는 직업으로 넘어갔다.
- 원인: 두 번 압축하면서 행동의 구체적인 모양이 사라진다. 코어 수를 18개로 늘려도 구조는 같다.

**[확정]** 6개 코어 → 직업 매핑(`hybrid_mapping_v2.csv`, `occ_core_scores_hybrid_v2.csv`)을 쓰지 않는다. 6개 코어는 인터뷰 판별 질문과 결과지 내부 태그로만 남긴다. 직업은 사람의 행동을 O*NET 업무 문장(Task)에 직접 대서 찾는다.

---

## 2. 전체 흐름

```
0. 행동 설명 만들기      (결과지 단계, LLM — 이미 하는 일)
1. 후보 업무 찾기        (LLM 1번 + 임베딩 검색 + 후보 직업 확장)
2. 판정                  (LLM)
3. 직업 점수             (코드)
4. 결과지에 보여주기     (코드 + 결과지 작성 LLM)
```
확정 코어(행동)가 여러 개면 행동마다 따로 돌리고 목록도 행동별로 따로 둔다. 두 행동에 모두 해당하는 직업을 억지로 찾지 않는다(시험에서 0개였다. 서로 다른 두 방향이라는 뜻이다).

### 0단계: 행동 설명
경험에서 나온 행동을 세 요소로 적는다. 대상 자리는 일반화하고 방식과 기준은 구체적으로 남긴다.

| 요소 | 예(글 흐름) |
|---|---|
| ① 동작 | 순서·배치를 바꾼다 |
| ② 다루는 것의 모양 | 이미 있는 여러 조각 |
| ③ 기준 | 전체가 매끄럽게 이어질 때까지 |
| (별도) 이 사람이 실제로 다룬 대상 | 글 |

결과지의 "파악한 코어" 문장이 거의 이 수준이라 새로 만들 게 많지 않다.

### 0-1. 두 경험이 같은 코어인지 (코어 이름 없이) **[확정 2026-09-26]**
코어 이름(여섯 단어)을 없앤 뒤에는 두 경험의 행동 설명끼리 같은 방식인지 **LLM이 판정**한다. 기존 코어 판정 단계(Opus)가 이름으로 맞추던 것을 대체한다. 새 단계를 추가하지 않는다.

| 경우 | 판정 |
|---|---|
| 동작과 다루는 것의 모양이 같다(대상만 다른 경우 포함 — 대상은 코어가 아니다) | 같은 코어 |
| 동작이 다르다(문단 순서 바꾸기 / 처음부터 새로 쓰기) | 다른 코어 |
| 동작은 같고 기준만 다르다(흐름 맞추려고 / 효율 높이려고 순서를 바꿈) | 같은 코어, 차이는 기록에 남긴다 |
| 일부만 겹친다 | 두 경험의 본인이 정한 부분끼리 겹치면 같은 코어. 겹치는 부분만으로 행동 설명을 새로 쓴다 |

- 판정마다 두 경험에서 사용자 표현을 하나씩 인용한다(검토 화면용).
- **애매하면 다른 코어로 둔다.** 같다고 하면 ② 방식의 반복이 생겨 확정이 쉬워지므로, 잘못 합치면 근거보다 부풀려 말하게 된다. 사람당 한 번이라 두 번 돌려 갈리면 다른 코어로 처리해도 비용이 작다.
- 같은 코어면: 두 경험의 대상이 같은 종류가 아닐 때 ②로 치고 두 경험의 신호를 합쳐 확정한다. 직업 목록의 확인된 대상에 두 경험의 대상이 모두 들어간다. 직업 검색은 합친 행동 설명 하나로 한다.
- 다른 코어면: 각 코어가 자기 경험의 신호로 확정되고 직업 목록도 각각 만든다.

### 1단계: 후보 업무 찾기 — 목표는 놓치지 않기
**1-1. 검색 문장 만들기 (LLM 1번)**
- 행동 설명을 검색용 대상 19개 각각에 끼워 넣은 영어 문장을 만든다. 업무 문장이 영어라서다.
- **바꾸는 건 대상뿐이다.** 방식과 기준은 남긴다.
  - 좋음: "arrange video scenes into a sequence so the story flows"
  - 나쁨: "edit video" — 음악 삽입, 색 보정 같은 영상 편집 전반이 끌려온다.
- 문장이 매끄러울 필요는 없다. 의미만 통하면 임베딩이 찾는다.
- 대상과 행동이 안 어울리면(예: 수식의 순서를 매끄럽게) "해당 없음".
- **[제안]** 대상을 안 넣은 문장도 1개 추가한다. 19개에 없는 대상을 잡는 안전망이다. 효과를 재서 계속 0건이면 뺀다(4절 참고).

**검색용 대상 19개** **[확정]**
- 10초 선택 화면의 15개: 신체 / 재료 / 기계·장비 / 공간 / 물건 / 생물 / 사람·관계 / 글·문서 / 데이터·숫자 / 코드 / 수식 / 개념·전략·규칙 / 그림·이미지·디자인 / 소리·음악 / 영상
- 검색 전용 4개: **일정·절차(작업 흐름)** / **돈·재무** / **조직·프로젝트** / **몸·건강(다른 사람의 몸)**
- 4개를 추가한 이유: 15개는 사람의 끌림을 보는 목록이라 직업 세계의 큰 대상 몇 개가 빠져 있다. 특히 일정·절차는 "순서 맞추기"가 많이 쓰이는 곳이다. 이 4개는 10초 선택 화면에는 넣지 않는다.

**1-2. 임베딩 검색 (코드)** **[확정: 키워드 검색은 쓰지 않는다]**
- 업무 문장 18,838개를 미리 임베딩으로 바꿔 둔다(한 번만).
- 검색 문장마다 가까운 업무를 **상위 30개씩** 가져온다. 문장끼리 경쟁하지 않고 각자 30칸을 가진다.
- **같은 문장이 여러 직업에 복사된 경우**(예: "Plan, evaluate, and revise curricula…"는 대학 교수 34개 직업에 있다): 검색은 문장 내용 기준으로 하나로 쳐서 30칸을 채운다. 판정도 한 번만 하고, 직업으로 바꿀 때 그 문장을 가진 모든 직업에 같은 점수를 넣는다.
- 업무 ID로 중복을 뺀다. 대상이 서로 겹쳐도 같은 업무는 한 번만 판정되므로 점수에 영향이 없다.
- 대상이 임베딩에 섞이는 문제는 오히려 이용한다. 대상을 빼려 하지 않고 대상마다 따로 검색해서 대상이 검색을 이끌게 한다.
- 검색 문장은 대상마다 **두 말투**로 만든다: 일상 말투 1개 + O*NET 업무 문장 말투(동사 + 대상 + 목적) 1개. 시험에서 설명 한 문장 검색은 강한 정답을 절반도 못 찾았고, 두 말투를 합치면 가장 많이 찾았다(5절).
- 검색 문장은 영어로 만든다. 한국어 문장은 영어 전용 모델에서 거의 0건, 다국어 모델(bge-m3)에서도 영어보다 크게 낮았다.
- **[제안]** 임베딩 모델: e5-base(무료 공개 모델). 시험한 4개(bge-small, bge-base, e5-base, bge-m3) 중 확장 방식(1-3)에서 가장 고르게 좋았고, 두 모델을 합쳐도 나아지지 않았다. 업무 임베딩은 미리 만들어 파일로 두고, 사람마다 새로 임베딩하는 건 검색 문장 40개뿐이다. 앱에서 어디서 돌릴지(서버에서 같은 모델 / 외부 임베딩 API로 업무 임베딩까지 다시 만들기)는 앱에 붙일 때 정한다. 업무 임베딩과 검색 임베딩은 같은 모델이어야 한다.

**1-3. 후보 직업 확장 (코드 + 2단계 판정)** **[확정 2026-09-26, 근거: 2026-09-25 임베딩 시험]**
- 검색 후보를 판정해 직업 점수를 한 번 매기고, A·B 각각 상위 40개 직업을 뽑는다.
- 그 직업들의 **업무 전부**(검색이 안 가져온 것 포함)를 판정해 점수를 다시 계산한다.
- 이유: 강하게 맞는 업무(0.7 이상)는 검색이 거의 다 찾지만, 약하게 맞는 업무(0.2~0.3)는 모델마다 절반쯤 놓친다. 직업 점수는 약한 업무가 쌓여 정해지는 경우가 많아서, 검색 후보만 판정하면 상위 10개 직업이 6~9개만 맞았다. 확장하면 진짜 상위 10개가 9~10개 후보 안에 들어오고, 그 직업들 점수는 정확해진다.
- 판정량: 행동 하나당 약 1,250~1,650문장(검색 후보 약 300~750 + 확장 약 900). 대부분 0점이다.

### 2단계: 판정 (후보 업무마다, LLM)
판정 기준은 **0단계 행동 설명**이다. 1단계의 끼워 넣은 문장은 쓰지 않는다.

출력:
1. **인용**: 업무 문장 중 행동에 해당하는 구절(원문 그대로)
2. **강도**: 채점 기준표에 따라
3. **몫**: 그 업무 문장 안에서 이 행동이 차지하는 비중
4. **이 업무의 대상**: 19개 중 무엇인지(표시만)
5. **이 사람의 대상과 같은가**: 예 / 아니오

**채점 기준표** — 대상 종류를 묻는 칸이 없다(이게 "대상을 무시한다"는 뜻)
| 강도 | 조건 | 예 |
|---|---|---|
| 1.0 강 | ①②③ 모두 맞음 | integrate component parts into desired sequences |
| 0.7 중 | ①② 맞고 ③이 안 적혀 있음 | rearrange schedules |
| 0.5 / 0.3 약 | 일부만 맞음 | edit video(순서 얘기 없음), create storyboards(새로 만듦) |
| 0 | 동작이 다름 | |

**판정 점수 = 강도 × 몫**

**몫 계산** **[확정 2026-09-26]**
- and로 묶인 서로 다른 행동은 몫을 나눈다. 예: "insert music, arrange into sequences, and correct errors" → 1/3
- or로 묶인 대안은 나누지 않는다. 하나라도 맞으면 몫 전체다(동사든 대상이든). "그중 아무거나 하는 업무"라 맞는 쪽을 골라 하면 업무 전체가 이 행동이기 때문이다. 예: "edit books, lesson plans, or tests"
- 이전 시험에서는 동사 or는 나누고 대상 or는 안 나눠서 기준이 달랐다. 이걸 바로잡는다.
- 문장을 문법 규칙으로 완전히 쪼개려고 하지 않는다. 시험 결과 규칙은 쓸수록 예외가 나왔다(부록 A). 대신 "행동에 해당하는 부분은 어디고 그게 얼마나 큰 몫인가"를 의미로 판단하게 하고, 쪼개기 규칙은 예시가 붙은 판단 가이드로만 준다.

**흔들림 대책** **[확정 2026-09-26]**
- 판정은 모든 문장 한 번씩만 한다. 1단계(검색 후보)와 1-3(확장)은 서로 다른 문장을 판정하므로 같은 문장을 두 번 보지 않는다.
- 이유: 1단계 판정은 후보 직업 40개만 고르면 되고 여유가 크다. 직업 점수는 여러 업무의 합이라 한 문장의 흔들림(0.5↔0.3) 영향이 작다(계산 방식을 바꿔도 상위권이 거의 같았다).
- 흔들림이 드러나는 곳은 결과지에 인용하는 근거 문장뿐이므로 그것만 한 번 더 판정한다(4단계 "근거 문장 재확인").
- 실제 LLM 판정이 얼마나 흔들리는지는 아직 재지 않았다. API로 한 번 재서 이 방식을 확인한다(비용 승인 필요).
- 코드 검사: 인용이 원문에 그대로 있는가, 값이 정해진 목록 안인가. 어긋나면 그 건만 다시 요청.

**감점(인터뷰의 부정 증거)** **[보류 2026-09-25]** 지금은 적용하지 않는다. 나중에 2차 트래킹(해 볼 일을 직접 해 본 뒤의 끌림)과 함께 다시 논의한다. 아래는 논의했던 규칙 기록이다.
- "해 봤는데 별로였다"일 때만 감점한다. 근거는 기록의 비교 선호(`comparison_preference`: 직접 해 봤고 `덜 끌림`)다. 질문흐름 v0.23부터 이건 확정 신호가 아니라 직업 추천용 기록이다. 질문흐름 v0.27부터는 따로 묻지 않고 사용자가 스스로 말했을 때만 기록되므로, 감점을 다시 논의할 때 근거를 어디서 얻을지(2차 트래킹 등)도 같이 정한다.
- "안 해 봤다"는 감점하지 않는다. 대신 2차 트래킹의 해 볼 일로 넘긴다. 스펙에도 "같은 대상의 다른 행동을 반드시 싫어해야 하는 것은 아니다"라고 되어 있다.
- 감점은 그 행동이 명확한 단위에만 한다(예: Write original…, Compose…). "애매" 표시된 단위와 revise·edit처럼 섞일 수 있는 단위는 감점하지 않는다.
- 감점해도 직업을 빼지 않고 순위만 내린다.
- 예: 이번 테스트 페르소나는 새로 쓰기를 "안 해 봤다"고 했으므로 작가 감점 대상이 아니다.

### 3단계: 직업 점수 (코드)
- 업무마다 원본 표(Task Statements)에 직업 코드가 붙어 있으므로 직업 코드별로 모은다.
- **직업 점수 = (그 직업에서 판정받은 업무들의 중요도 × 판정 점수 합) ÷ (그 직업 전체 업무의 중요도 합)**
  - 중요도: Task Ratings의 IM(1~5, 그 직업 종사자가 답한 평균)
  - 분모는 후보가 아니라 원본 표에서 그 직업의 업무 전부. 예: 테크니컬 라이터 업무 15개, 중요도 합 62.1
  - 뜻: 그 직업이 하는 일 중 이 사람의 행동이 차지하는 몫
- **B 목록(대상 제외)**: 판정 점수가 있는 업무를 대상 상관없이 전부 넣은 순위표 하나
- **A 목록(대상 포함)**: 그중 "이 사람의 대상과 같다"인 업무만으로 계산
- A는 B의 부분집합이라 판정 한 번으로 두 목록이 다 나온다.
- **[제안]** 빈도(FT: 매년~매시간 7단계)나 관련도(RT: 종사자 중 몇 %가 하는지)를 가중치로 섞을지는 시험 후 결정한다.

### 4단계: 결과지에 보여주기 **[확정 방향, 세부 문구 결정 필요]**
- B 순위표 위쪽은 대개 이 사람의 원래 대상 직업이 차지한다. 행동이 그 대상에서 나왔으니 당연하다. 그래서 대상 표시로 나눠서 보여준다.
  - **"확인된 대상에서 이어지는 일"** = A. **[확정 2026-09-26]** 확인된 대상 = 경험의 대상 + 인터뷰에서 ② 방식의 반복으로 확인된 다른 대상(질문흐름 v0.28의 other_object). 예: 자소서에서 발견되고 영상에서도 같은 방식이 확인됐으면 글·문서와 영상 둘 다 A다. 비슷한 대상(자소서 → 보고서)은 검색용 대상 분류로 같은 "글·문서"라 A가 달라지지 않는다.
  - **"아직 확인 안 된 대상에서 쓰이는 일"** = B에서 A의 대상이 아닌 직업을 대상별로 (예: 영상 → 영상 편집자·감독 / 디자인 → 그래픽 디자이너 / 일정·절차 → 생산 계획). 2차 트래킹의 해 볼 일 후보다.
  - **직업의 대상**: 판정 단계에서 업무마다 대상을 표시해 두므로, 한 직업의 대상은 그 직업 점수에 가장 많이 기여한 대상(업무 중요도 × 판정 점수의 합이 가장 큰 대상)으로 정한다.
- **[확정 2026-09-26] 보여줄 직업 수**: 확인된 대상(A)에서 최대 5개, 아직 확인 안 된 대상에서 최대 5개.
  - A: 점수순. 확인된 대상이 여러 개면 대상마다 최소 1개씩 먼저 넣고 나머지를 점수순으로 채운다.
  - 아직 확인 안 된 대상 5개: 대상마다 1등 직업을 하나씩 뽑고, 그중 점수가 높은 5개를 보여준다(2차 트래킹의 해 볼 일 후보라 대상이 다양해야 한다). 대상이 5개가 안 되면 남은 칸을 점수순으로 채운다.
  - 근거를 통과한 직업이 모자라면 채운 만큼만 보여준다. 점수가 낮은 직업으로 억지로 채우지 않는다.
- **[확정 2026-09-26] 코어가 두 개일 때**: 코어마다 확인된 대상 3개 + 아직 확인 안 된 대상 3개(총 12개). 코어가 하나면 5+5. "더 보기"로 늘리지 않는다. 근거가 강한 코어를 먼저 둔다. 두 코어에 같은 직업이 걸리면 점수가 높은 코어 쪽에 한 번만 보여주고 "두 코어 모두 쓰이는 일"로 표시한다.
- **[확정 2026-09-26] 화면 배치**: 세로 목록(옆으로 넘기는 카루셀은 쓰지 않는다 — 넘겨야 보이는 항목은 잘 안 보고, 일치도를 나란히 비교하기 어렵다).
  - 코어 칸 안에 두 소제목("확인된 대상에서 이어지는 일" / "아직 확인 안 된 대상에서 쓰이는 일")을 두고 그 아래에 직업을 한 줄씩 놓는다.
  - 직업 한 줄 = 직업 이름 + 한 줄 직업 설명 + 일치도 숫자.
  - 직업을 누르면 펼쳐져서 근거 업무 인용을 보여준다.
  - **[제안]** 직업 이름·한 줄 설명(한국어)은 사람마다 새로 쓰지 않고, 1,016개 직업을 미리 한 번 만들어 두고 검토해서 쓴다(비용이 한 번뿐이고 사람마다 설명이 달라지지 않는다).
- **[확정 2026-09-26] 근거 문장 재확인**: 판정은 모든 문장 한 번씩만 한다. 결과지에 인용할 근거 문장(0.5 이상)만 한 번 더 판정한다. 두 판정이 갈리면 그 직업의 다음 근거 문장으로 넘어가 다시 확인한다. 통과하는 근거가 없으면 그 직업을 빼고 다음 순위 직업을 올린다.
- **[확정 2026-09-26] 일치도 숫자**: 직업 점수(그 직업이 하는 일 중 이 행동이 차지하는 비중)를 **고정 기준값**으로 나눠 100점 만점으로 바꾼다.
  - 일치도 = min(100, 직업 점수 ÷ 기준값 × 100), 정수로 보여준다.
  - 기준값은 사람마다 바꾸지 않는 고정값이다. 사람마다 1등을 100으로 맞추면 누구든 1등이 100이 되어 숫자가 뜻을 잃는다.
  - **[확정 2026-09-26] 기준값 25%.** 시험 두 행동에서 상위권 직업 점수가 대부분 15~25%였다. 20%로 잡으면 상위 6개가 모두 100이 되는 목록이 생겨(글 흐름 B, 챙기기 B) 구분이 안 된다. 25%면 예: 가족 치료사 22.4% → 90, 정신건강 상담사 18.0% → 72, 편집자 15.5% → 62, 영상 편집자 45.9% → 100(상한).
  - 기준값은 행동 두 개로 정한 임시값이다. 실제 사용자 결과가 쌓이면 상위권 점수 분포를 보고 한 번 다시 정한다. 정한 뒤에는 자주 바꾸지 않는다(바꾸면 예전 결과지와 숫자 뜻이 달라진다).
- **[확정 2026-09-26] 인용 기준**: 결과지에 인용하는 근거 업무는 판정 0.5 이상만 쓴다. 직업 점수 계산은 0.2·0.3 업무도 그대로 포함한다(계산 방식을 바꿔도 상위권이 거의 같았다). 약한 업무만 쌓여 올라온 직업은 인용할 근거가 없으므로 위 "근거 문장 재확인" 규칙에 따라 빠진다.
- 직업마다 **근거 업무 문장 인용**과 **확인된 범위**를 같이 보여준다. "당신에게 맞는 직업: ○○"가 아니라 "당신이 자소서에서 한 일이 이 직업의 실제 업무예요(인용). 지금은 글에서만 확인됐어요."
- 1차 결과지에 "이 목록은 지금 경험의 대상 기준이고, 대상은 바뀔 수 있다"를 적는다.
- "다른 대상에서도" 목록이 그대로 2차 트래킹 전 해 볼 일이 된다(예: 영상 클립 순서 맞춰 보기, 일정표 다시 짜 보기). 2차에서 다른 대상에서도 끌리면 B 확정, 아니면 A 확정. 코어와 대상을 가르는 실험이 된다.
- **[확정] Job Zone(준비 수준)은 쓰지 않는다.** 직업은 행동으로만 구분하는 게 핵심이라, 준비 수준으로 거르거나 묶지 않는다(2026-09-25 결정). `data/onet31/occupations.json`의 jobZone 값은 남아 있지만 쓰지 않는다.
- **[확정] 종교·장례 직업 8개는 직업 코드로 제외한다**(`data/onet31/excluded_occupations.json`: 성직자, 종교 활동·교육 책임자, 그 밖의 종교 종사자, 장례식장 관리자, 시신 방부 처리사, 화장 기사, 장례 보조원, 장례 지도사). 철학·종교학 교수는 남긴다. 다른 직업 안에 섞인 종교·장례 맥락 업무 문장(예: 병원 직원의 유족 위로)은 코드로 못 거르므로, 판정 단계에서 맥락이 다르면 점수를 주지 않는 규칙으로 거른다.
- **[확정 2026-09-26] 결과지에서 없애는 것**: "세 직업을 가르는 질문"(직업이 12개로 늘어 질문 하나로 못 가르고, 경험과 안 이어지는 직업을 거르려던 원래 목적도 새 방식에선 필요 없다), "직무와 연결하면" 칸(쓰일 수 있는 일은 새 직업 목록과 겹치고, 아직 모르는 것은 "아직 확인 안 된 대상" 목록이 대신한다. 면접용 한 문장 say는 저장만 계속한다). 예전 "어울리는 직업 3개"의 연결되는 부분·아직 확인 안 된 부분·떠올려 볼 장면도 없앤다.
- **[확정 2026-09-26] 번역은 미리 한 번만**: 직업 1,016개의 한국어 이름·한 줄 설명은 미리 만들어 검토해 둔다. 근거로 인용하는 업무 문장은 처음 쓰일 때 한 번 번역해 저장하고 다시 쓴다(사람마다 번역이 달라지지 않게).
- **[확정 2026-09-26] 대상 섹션 삭제**: 결과지의 "대상" 섹션을 없앤다. 맨 위 요약 카드의 "고른 대상"은 남긴다. "대상은 바뀔 수 있다"는 코어 칸 안 직업 목록 맨 위에 한 줄로 둔다(예: "지금은 이번 경험의 대상을 기준으로 골랐어요. 대상은 살면서 바뀔 수 있어서, 같은 행동이 쓰이는 다른 대상의 일도 함께 보여드려요."). 이 문장이 두 목록이 왜 있는지도 설명한다. 코어가 두 개면 첫 번째 직업 목록 위에만 둔다.
- **[확정 2026-09-26] 펼쳤을 때**: 근거 업무 인용만 보여준다(연결 문장은 붙이지 않는다 — 판정이 맞으면 근거가 곧 연결이고, 지어낼 여지가 생긴다). 판정 때 뽑은 "행동에 해당하는 구절"을 굵게 표시한다.
  - 구절은 영어 원문에서 뽑히므로, 근거 문장을 번역할 때 그 구절을 표시(예: [[...]])로 감싸 주고 한국어에서도 해당 부분을 같은 표시로 감싸게 한다. 코드가 표시가 한 쌍만 있는지 확인하고, 아니면 굵게 없이 보여준다.
  - 같은 업무 문장이라도 행동마다 해당 구절이 다를 수 있어서, 번역 저장은 (업무 문장, 구절) 단위로 한다.
- **[확정 2026-09-26] 관리자·임원급 직업 제한 없음**: 새 방식에선 관리 업무 비중 때문에 순수 관리자·감독자 직업이 30위 밖으로 자연스럽게 밀린다(시험: 모금 관리자 38위, 사회복지 서비스 관리자 30위 등). 반대로 제목에 "디렉터"가 들어간 창작직(음악 감독 7위, 아트 디렉터 12위)은 맞는 결과라 이름으로 자르면 안 된다. 예전 "관리자급 최대 1개" 규칙은 쓰지 않는다.

## 3. 검증 계획

- **정답지**: 두 행동의 후보 업무 중 40개 정도. 제가 이유를 붙여 먼저 판정하고, 기준을 정해야 하는 경계 사례 10개 정도만 님이 판정한다. 정답지는 "무엇을 맞다고 칠지"라는 서비스 기준을 데이터로 박아 두는 역할이다.
- **재는 것**
  - 1단계 재현율: 정답지에서 "맞다"인 업무가 후보에 들어왔는가
  - 2단계 정확도: 들어온 후보를 맞게 판정했는가
  - 3번 판정 일치도, "애매" 표시가 실제로 어려운 것을 잡았는가
  - "대상 없음" 검색에서만 걸린 정답 수
- **독립 측정**: 새 맥락(별도 에이전트 또는 API)에서 해야 한다. 같은 대화에서 두 번 판정하면 앞 결과가 기억에 남아 일치도가 부풀려진다.

## 부록 A. 업무 문장 쪼개기 규칙 시험 (200개, 2회)

- 규칙 v1(동사 단위, to부정사·~ing·관계절 제외, 행동 종류 9개 표로 합치기/나누기, 대상 나열은 안 나눔)으로 무작위 200개를 두 번 쪼갰다.
- 완전 일치 192/200(96%). 쪼갤 게 있는 59개만 보면 51/59(86%). 같은 대화 안의 두 번이라 부풀려진 상한선이다.
- 갈린 유형: 목적이 여러 개일 때 / 같은 대상인지 / 표에 없는 동사
- 더 중요한 발견: 두 번 다 똑같이 틀린 경우는 일치도에 안 잡힌다. "…, organizing material accordingly"처럼 ~ing 구문에 진짜 행동이 있는데 규칙이 버렸다.
- O*NET의 업무→DWA 연결은 쪼개기를 대신하지 못한다(업무의 76%가 DWA 1개, 우리 단위 수와 맞는 건 56개 중 16개).
- 결론: 규칙을 끝까지 하드코딩하는 방식은 버리고, 2단계 판정에서 의미로 판단하게 한다(2절 2단계).
